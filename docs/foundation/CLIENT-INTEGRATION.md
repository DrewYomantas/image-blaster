### Proposed TPS adapter

Export an engine-owned asset package for review/import into Unreal, without writing to the TPS checkout. Prefer modular static meshes, separable material slots and explicit semantic part IDs for scenery/building components; retain source scale/pivot/frame and collision status. Retain concept references and splats as optional atmosphere/background studies. A splat is not authoritative traversable terrain, navigable architecture, water, occlusion, collision, clearance, construction state or an attraction-course model.

Attach existing client identity and revision only when supplied. Preserve map-owned terrain/water/roads/features and C# snapshots. An adapter can map accepted semantic object/part IDs to candidate visual assets; it must not invent a new client entity, acquire land, construct a building, mutate simulation, or derive a save from the prompt. Future component replacement and durable overrides need explicit mappings rather than one merged scene.

TPS map horizontal coordinates are `XCm`/`ZCm`; height is separate. Existing Unreal land realization maps `(xCm, zCm, heightCm)` to Unreal `(X,Y,Z)` centimetres (`ParkLandWorld.cpp`). Asset frame conversion must declare axis permutation, handedness, winding, scale and pivot separately. Do not reuse a Benson inch transform. Keep inferred scale distinct from verified dimensions.
