# Provider and model research

Research date: **2026-10-03**. Primary sources were read during this pass. This is a capability and procurement study, not a generation benchmark or legal clearance. No model was installed or run, no paid task was submitted, and no customer image was uploaded. Release dates below come from dated official sources; undated live documentation establishes availability observed on the research date, not an October release. Exhaustive October release coverage is **unknown**.

## Recommendation

Build a provider-neutral, local artifact pipeline with separate stages for **analysis/masks**, **object generation**, **observed-scene reconstruction**, **world generation**, **materials**, and **audio**. Start with dry-run and imported fixtures. Retain the existing endpoint-selected hosted Hunyuan v3 adapter and Marble 1.1 adapter as candidates, and compare hosted Meshy/TRELLIS.2 only in a later explicitly budgeted evaluation. Their immutable vendor checkpoint identity is unknown. Explore Apache-licensed Depth Anything 3 Base/Small or commercial VGGT for a separate reconstruction track. Do not make a self-hosted CUDA stack the foundation for this AMD Windows desktop.

This is an architectural recommendation, not a claim that any provider meets acceptance. A single-image generated asset fills unseen surfaces using learned priors; it cannot establish an observed room, product dimension, clearance, safe installation, collision truth, or measured geometry. For TPS, generated scenery can support art reference and decorative asset drafts. For Benson, it can support clearly labeled visual studies, while source-backed product geometry, dimensions, manuals, and recorded measures remain authoritative.

The checked-in adapters currently select `fal-ai/hunyuan3d-v3/image-to-3d`, `fal-ai/meshy/v6/image-to-3d`, `marble-1.1`, and ElevenLabs audio through fal. ## Cost notation and comparison limits

All USD figures are observed public list prices or explicit arithmetic, before tax, storage, retries, and cleanup. API credit prices and cloud capacity can change. Hosted latency includes unknown queue effects unless a provider states otherwise. Research-paper timing is not application end-to-end timing. Quality statements describe capability and failure risk, not an independently established winner.

Self-host planning estimates use the live [Runpod price table](https://www.runpod.io/pricing): RTX 4090 24 GB $0.74/hour, A6000 48 GB $0.53/hour, A100 80 GB $1.59/hour, and H100 SXM 80 GB $3.49/hour. These are rental references, not services authorized or provisioned here. Formula: `GPU count × billed hours × hourly rate`. For an owned machine, inference has no API charge but power, depreciation, engineering, and licensing still apply. Acquisition and local electricity costs are **unknown**.

The assumed runtime windows in the tables are **budget envelopes**, not measured predictions. If a model has no trustworthy minimum VRAM or timing in the consulted docs, that fact remains unknown. Maintenance estimates are qualitative: low means a hosted schema integration; medium means a Python/checkpoint service; high means custom native GPU components or multiple model stages.

## Object generation

### TRELLIS.2

Microsoft's 4B image-to-3D model supports 512³–1536³ representations and base color, roughness, metallic, and opacity. Official requirements specify Linux testing and NVIDIA VRAM of at least 24 GB; A100/H100 are verified by the authors. Published H100 shape/material times are about 3/17/60 seconds at the three resolutions, excluding a promise about complete app processing. The sample exports PBR GLB and a rendered MP4; opacity defaults to inactive OPAQUE rendering. Shape-conditioned texturing is also available. Native Windows or this AMD desktop execution is **unverified**. [Official repository](https://github.com/microsoft/TRELLIS.2).

Code is [MIT](https://raw.githubusercontent.com/microsoft/TRELLIS.2/main/LICENSE); the [weight card](https://huggingface.co/microsoft/TRELLIS.2-4B/raw/main/README.md) also declares MIT. **The default stack is not commercially cleared by those declarations alone.** The actual [setup script](https://raw.githubusercontent.com/microsoft/TRELLIS.2/main/setup.sh) installs `NVlabs/nvdiffrast` at `v0.4.0` and `JeffreyXiang/nvdiffrec` at `renderutils`. Section 3.3 of those exact [nvdiffrast license](https://raw.githubusercontent.com/NVlabs/nvdiffrast/v0.4.0/LICENSE.txt) and [nvdiffrec license](https://raw.githubusercontent.com/JeffreyXiang/nvdiffrec/renderutils/LICENSE.txt) files limits use to non-commercial research/evaluation. Whether replacing those paths preserves acceptable results is **unknown**. Resolve dependencies or obtain permission before a commercial self-hosted pipeline.

## World generation and reconstruction

### World Labs Marble

Official release notes date Marble 1.1/1.1 Plus to April 2, 2026. The World API lists explicit 1.0 Draft, 1.0, 1.1, and 1.1 Plus model IDs; its default is currently 1.0 and is scheduled to change. Always send a model ID; immutable checkpoint identity is unknown. [Release notes](https://docs.worldlabs.ai/marble/release-notes), [API models](https://docs.worldlabs.ai/api/models).

API output can include SPZ visual splats and a GLB collider. Export API separately supports PLY splats and asynchronous HQ GLB meshes, textured or vertex colored. Full, 500k, 150k and 100k splat tiers are documented. These are distinct representations, not interchangeable engine assets. [Export API](https://docs.worldlabs.ai/api/reference/worlds/export), [file specifications](https://docs.worldlabs.ai/marble/export/specs). HQ meshes are approximately 600k triangles with texture or 1M with vertex color and can have holes, floaters and blobby geometry. Provider documentation allows up to an hour for mesh generation. Roughness/metallic/normal PBR maps and robust relighting of splats are **not established** by these docs. [Mesh limitations](https://docs.worldlabs.ai/marble/export/mesh).

## TypeSafe Jev / System One

Jev is **a typed decision service, not an image-to-mesh or world generator**. The official launch is September 15, 2026 and describes early access. It sacrifices general string generation for probabilistic decisions. Speed/accuracy claims are vendor evaluations, not project proof; type-valid output can still encode an incorrect decision. [Launch](https://typesafe.ai/blog/introducing-system-one-models-and-jev).

The [API reference](https://api.typesafe.ai/redoc) accepts state plus named questions, returns typed answers/probabilities and usage, and discovers available models via an authenticated `GET /v1/models`. `jev-latest` is a mutable alias. The [launch](https://typesafe.ai/blog/introducing-system-one-models-and-jev) states $0.042/million input tokens ($42/billion) and **free output tokens**. That is $0.000042 per 1,000 billed input tokens, an arithmetic estimate before any unverified additional billing rules. [Public price](https://typesafe.ai/). Exact account prices, availability, quotas, retention and commercial API contract are **unknown** without authenticated/account-specific evidence; launch-stated free output does not substitute for an account contract. Public [website terms](https://typesafe.ai/legal/terms) do not establish a complete API procurement contract.

Windows/Linux HTTP client execution requires no local GPU. Weights, self-host license, OS support, VRAM, PBR/formats and self-host cost are **not available/not applicable** for the considered hosted service. Maintenance is low/medium but early-access versioning matters. Potential TPS/Benson role: classify a recorded source state as suitable for reconstruction, object generation or human review; select from bounded known options; assign a quality-review probability. It must never create missing measurements, approve installation clearance, or replace deterministic validators. Use it only after ordinary rules leave a real classification problem and a small task-specific evaluation establishes utility.

## Acceptance gates before adoption

1. Record provider, exact endpoint/model/checkpoint revision, execution environment, seed/config, input hashes, license/terms reference, estimated maximum and settled cost. Treat hosted and self-hosted rights as different records.
2. Test a tiny common fixture set: isolated decorative prop, thin/reflective object, multi-view observed room, and one source-backed product with known dimensions. Compare silhouette, unseen-surface invention, UVs/material channels, topology, scale, artifact size and cleanup time. No provider ranking is established until this runs.
3. Validate actual artifacts: parsable local GLB, named material channels, texture availability, splat tier/scale, collider role, units/axes and engine/DCC import. PBR flag or `.glb` extension is not sufficient evidence.
4. Validate acceptance separately: TPS runtime cost, collision, authored park semantics and playtest; Benson visual truth, manual product requirements and real installation measurements. Neither provider marketing nor an automated parser establishes these.
5. Require an explicit budget and permitted input set for paid evaluation. Persist job IDs before retries, reconcile uncertain submissions and prevent automatic duplication. In particular, Marble's prepaid balance is not a hard cap.

**Narrow decision:** keep the foundation local and provider-neutral, with one existing hosted object adapter and one existing hosted world adapter behind explicit execution gates. Add a separate reconstruction interface and reserve Apache Depth Anything 3 Base/Small or VGGT's specific commercial checkpoint for the next evidence pass. Keep TRELLIS.2 self-host, full HY-World, MaterialAnything, broader audio and Jev as optional research tracks until licensing, hardware and fixture evidence justify them.
